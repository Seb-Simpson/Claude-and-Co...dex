## One application, replaceable sessions

`src/main.ts` discovers the existing modules and delegates to
`createApplication()` in `src/integration/application.ts`. The application owns
one engine, renderer, scene, camera and Rapier backend. Each attempt owns a new
module registry and typed event bus. Restart stops the current loop interval,
disposes all modules in reverse order, and constructs a fresh hospital, player,
Patient, doors, hiding occupancy and atmosphere against the same engine.

The registered `night-ward:gameplay` definition is configured through its public
factory: Patient only, 0.25m navigation cells, existing hospital inspection text,
and a restart callback. All authored spawn/route metadata remains in the world;
secondary physical actors are deliberately not enabled before their encounters
are ready. Their four-model showcase coverage remains intact; the real-entry
asset tests verify the configured Patient-only assembly, all five GLB responses
and procedural fallback. The Reflection remains a nonphysical visual encounter.

States are loading → ready → playing → captured → restarting → ready. Ready
freezes simulation until the player acquires pointer lock. Captured freezes
player/AI fixed updates, releases the mouse and presents a fade with Restart.
Rendering/presentation continues through the transition. The engine alone steps
physics; no adapter adds an independent renderer, RAF or physics loop.

Each attempt rebases the authoritative simulation clock. Event subscriptions,
entities, furniture/door animation state, model resources, ambient voices,
chase pulses and hiding occupancy are released before a new attempt. Fatal
startup/WebGL errors stop the application and release the backend. Disposal is
idempotent and waits for asynchronous setup/restart work already in progress.

## Functional integration

- All authored collision definitions are imported; the real room104 feet/yaw
  spawn is used. Floors, walls, furniture and dynamic doors remain solid.
- Interaction rays target registered marker branches and use actual physics LOS.
  Material-invisible bed proxies still raycast; genuinely invisible object
  branches do not. Door offsets are derived from the authored initial hinge pose.
- Locker child objects named `door` animate around their provided hinge during
  entry/exit. Furniture collision is not globally disabled. The hidden capsule
  remains reserved and only the spot's assigned envelope is ignored for its
  validated entry/exit corridor. All four lockers and both beds have tested exits.
- Drawers and cabinets perform contextual inspections and display text outcomes.
  They are authored merged geometry, so no fabricated independent drawer mesh is
  animated. The ward board, lift and stair notice also provide local feedback.
- The Patient starts at its maintenance spawn and joins the nearest authored
  ward-loop point. It opens nearby ordinary doors through the same swept,
  occupancy-aware system, and can approach a reachable doorway when a route is
  blocked. Locked doors stay locked.
- Vision/sound drive pursuit, last-known search and loss of target. Capture uses
  grace and contact dwell. Witnessed furniture inspection has its own bounded
  2m reach from a reachable authored approach; ordinary visible capture range
  stays 0.85m. Occupied/distant approaches still prevent capture. No encounter
  teleports an enemy or forces a capture.
- `createPatientEncounter()` subscribes to existing chase/capture events and
  provides contextual messages. When the installed `nw:horror-layer` supplies
  NW-002B presentation, the adapter allocates no legacy audio voices and emits no
  duplicate chase lighting/sound cues. Without that layer it supplies restrained
  fallback effects through the shared audio service and existing event contracts.

## Public application API and QA

```ts
createApplication(options: ApplicationOptions): Application
// Options: container, modules, gameplayOptions?, engineFactory?, onStatus?, onState?
// Application: start(), play(), restart(), dispose(), snapshot(),
//              teleport(position,yaw?), aimAt(position), captureForTest()
```

The last three scenario controls are only exposed on `window.nightWardTest`
when the URL explicitly contains `?test=1`. They are not installed in normal play.
The typed bridge in `src/integration/testing.ts` reports session/state, player,
entity snapshots, door states, prompt, bounded event history, audio state,
physics collider count, renderer memory/draw counts and update timing maxima.
Positioning validates collision/support and is test setup, not an escape mechanic.

`Engine.getPerformanceSnapshot?()` additionally exposes a fixed 240-frame timing
window, cumulative frame/substep counts, and `{last,mean,p50,p95,max}` for raw RAF
intervals, total CPU time, all fixed callbacks, Rapier steps, presentation update,
renderer submission and substep count. `snapshot().performance.engine` contains
that window; `performance.simulatedSeconds` counts actual playing updates.
Sampling uses fixed storage; percentiles are calculated only when inspected.
Pause gaps are excluded and restarting clears session measurements. Render CPU
submission timing is not a GPU timer. The older `frameDeltaMaxMs` is still the
clamped simulation delta and must not be interpreted as wall-clock FPS.

See `src/entities/README.md` and `src/gameplay/README.md` for owned factories.
New integration surfaces include `createDoorNavigationAdapter()`,
`InteractionSystem.requestDoorOpen()`, `GameplayRuntime.notify()` and
`createPatientEncounter()`.

```ts
createPatientEncounter(options: PatientEncounterOptions): PatientEncounter
// Options: events, audio, playerId?, onMessage?, presentationProvided?
// Result: readonly activeChases, update(frame), dispose()

createDoorNavigationAdapter(options: DoorNavigationOptions): DoorNavigationAdapter
// Options: world, physics, navigation, agent, getDoorState, requestDoorOpen,
//          interactionDistance?

```

## Performance and limits

Immediate Rapier queries now use a conservative spatial grid; door pose changes
refresh it synchronously. Navigation caches clearance, segments and paths against
an obstacle revision and invalidates on every moved door. No colliders are
removed to improve navigation or benchmarks. A separate vertical/planar capsule
pass prevents floor-seam contact noise from lifting a character through geometry.
Tangential box sweeps use exact separating planes so inflated contact skin cannot
turn a floor edge into a wall; vertical/inward sweeps retain their collision skin.
Thirteen doorway regressions include the exact positions found by browser testing.

A reported delayed slowdown was reproduced on the original closed-door layout
when the Patient reached the east maintenance door after roughly 104 simulation seconds. Local door approaches now
take priority over full-hospital detour searches. On the opening side the approach
waits outside the leaf's swept arc, so the Patient does not block its own door or
repeat cold searches during the animation. Collider occupancy, line of sight and
path validation remain authoritative. See the retained
[navigation measurements](evidence/nw-002a/navigation-profile.json).

An identical blocked query against main's linear collision scans and uncached
navigation took 4,071 ms, then 3,726 ms again. With spatial indexing and caching,
the same 0.5m-grid query took 79 ms cold and 0.02 ms repeated. The finer 0.25m
hospital grid can still cost 306 ms for that artificial blocked query; local-door
planning avoids it during ordinary patrol. In the measured 120-second patrol,
the worst navigation query fell from 353 ms to 0.71 ms, with 0.37 ms at p95.
On the final Claude layout, the 120-second patrol measured a 0.72 ms maximum
navigation query and 0.43 ms at p95; both initially closed service doors reopened
safely. A separate run had a 13.49 ms outlier, and a remote blocked-goal/noise
scenario produced a 48.77 ms cold query. The JSON also retains measurements from
the intermediate 16-leg layout. These
CPU-only Node measurements are not hardware guarantees or browser FPS results.
Navigation handles this hospital floor;
it conservatively refuses stairs/multiple floor connections and budget overruns.
Door rotation uses conservative subdivisions rather than general rotational CCD.

The build retains the Rapier/WASM large-chunk warning. Browser runs use headless
software WebGL, so hardware GPU performance and other browsers remain unverified.
Saving, final escape progression and finished secondary encounters are outside
this first playable. Stairwell B remains deliberately locked.

## NW-002B / NW-002C presentation integration

The merged presenter binds the NW-002C animated Blender Patient to the existing
gameplay node automatically. Hospital module setup awaits model loading before
the application becomes ready, with the module's procedural fallback on failure.
Its procedural score, positional entity
audio, footprints and cinematic chase transitions own presentation; the gameplay
adapter does not duplicate them. Secondary entity assets are available, but their
physical encounters remain disabled pending dedicated gameplay integration.

Claude's Room 104 and west-corridor set also loads before the world is published.
It changes visuals while retaining all 223 collision definitions, interaction
markers, hiding metadata and spawns. `?nwSet=procedural` forces its documented
fallback. Both modes remain covered by the preserved visual prototype tests.
Model instance cleanup includes the imported skeleton disposal fix; repeated
restart tests check GPU resource counts after fresh rendered frames.

For future model replacements, attach a direct child of the feet-pose node
`night-ward:entity:nw:entity:patient`. Its forward axis is -Z and units are metres.
The temporary proxy automatically hides while another direct child is attached,
or when `node.userData.nwEntityModelReady = true`. Attach the completed model only when it is ready, and ignore asynchronous loader
completions after module disposal. The attaching module owns its
materials, geometry, animation updates and cleanup. Removing the model/flag
restores the fallback. Do not add a second enemy mover, collider or render loop.

Atmosphere/horror can continue to subscribe to `chase:started`, `chase:ended`,
`player:captured`, `horror:reflection` and existing sound/lighting events. Match
lifecycle notifications by chaseId. New visual modules should implement dispose
so capture/restart removes their animation/audio/event resources before rebuild.
